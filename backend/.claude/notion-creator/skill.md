# Notion 페이지 작성 스킬

사용자가 특정 Notion 페이지에 내용을 정리해달라고 하면 아래 순서와 규칙에 따라 작성.

## 작업 순서

### 1단계: 소스 읽기

소스가 URL이면 `WebFetch`로 전체 내용을 가져옴. 텍스트나 파일이면 그대로 활용함.
내용이 길거나 섹션이 많으면 전체를 빠짐없이 파악한 뒤 구성에 들어감.

### 2단계: Notion Markdown 스펙 확인

`ReadMcpResourceTool`로 `notion://docs/enhanced-markdown-spec` 리소스를 읽어서
Notion이 지원하는 정확한 마크다운 문법을 확인함.

이 단계를 건너뛰면 Callout, Toggle, Table 같은 블록이 렌더링되지 않거나 깨질 수 있음.

### 3단계: 대상 페이지 상태 확인

`mcp__notion__notion-fetch`로 대상 Notion 페이지를 조회함.
페이지 ID와 현재 내용을 확인하고, 기존 내용을 덮어쓸지 추가할지 판단함.

### 4단계: 내용 구성

아래 포맷 규칙에 따라 내용을 구성함.

### 5단계: Notion 업데이트

`mcp__notion__notion-update-page`로 페이지에 실제로 작성함.
command는 기존 내용을 모두 교체하는 `replace_content`를 기본으로 사용하고,
내용을 추가해야 하는 경우에만 `insert_content`를 씀.

## 포맷 규칙

### 제목 계층

Notion 데이터베이스 항목의 페이지 제목은 속성(property)으로 별도 관리되므로,
페이지 내용 영역에서 `#` (H1)을 대섹션 제목으로 자유롭게 써도 됨.

- 대섹션 구분 → `#` (H1) — 구분선(`---`)을 바로 아래에 추가해 섹션 경계를 명확히 함
- 세부 항목 → `##` (H2)
- 그 이하 계층이 필요하면 `###` (H3) 또는 들여쓰기 불릿으로 처리

**중요 섹션 강조:** 특별히 주의가 필요하거나 핵심인 섹션 제목은 `<span color="red">제목</span>` 형태로 빨간색 강조.

```
# 일반 섹션
---

# <span color="red">핵심 주의 섹션</span>
---
```

### 본문 스타일: ~~했음 체, 볼릿 포인트 (핵심)

모든 본문은 `-` 로 시작하는 불릿 포인트로 작성하고, 중요한 본문은 빨간색 글씨로 표시
단락 형태의 긴 서술보다 불릿 포인트로 핵심만 간결하게 정리하는 게 읽기 편함.

**상황별 어미:**

- 상태·특성 설명 → `~~임`, `~~있음`, `~~없음`
- 동작·완료 설명 → `~~했음`, `~~됨`, `~~쓰임`
- 가능성·주의 설명 → `~~수 있음`, `~~안 됨`, `~~주의해야 함`

**어투 변환 예시:**

```
❌ 합쇼체 (쓰지 말 것)
- Context Window는 Claude가 기억할 수 있는 대화의 총량입니다.
- 이 파일은 매 대화 시작 시 자동으로 로드됩니다.
- 너무 길면 Claude가 중요한 규칙을 무시합니다.

✅ ~~했음 체 (이렇게 쓸 것)
- Context Window (Claude가 기억할 수 있는 대화의 총량)임
- 매 대화 시작마다 자동으로 로드됨
- 너무 길면 Claude가 중요한 규칙을 놓칠 수 있음
```

### 전문 용어 처리

전문 용어나 영어 단어가 나오면 바로 옆에 괄호로 쉬운 설명을 달아줌.
독자가 검색하지 않아도 바로 이해할 수 있도록 하기 위해서임.

```
✅ 좋은 예
- Context Window (Claude가 한 번에 기억할 수 있는 대화의 총량)가 가득 차면 성능이 떨어짐
- Plan Mode (파일을 읽기만 하고 수정은 하지 않는 안전한 탐색 모드)를 먼저 사용하는 게 좋음

❌ 나쁜 예
- Context Window가 가득 차면 성능이 떨어집니다.
- Plan Mode를 먼저 사용하세요.
```

### 표 활용

여러 기능·항목을 비교하거나 정리할 때는 표를 적극 활용함.
특히 **기능 소개**처럼 여러 속성을 가진 항목들은 "설명 + 사용 시기 + 예시" 컬럼을 포함한
통합 표 하나로 한눈에 비교할 수 있게 만드는 게 좋음.
각 기능마다 별도 소제목+단락으로 나누는 것보다 표가 훨씬 스캔하기 쉬움.

반드시 Notion 표 문법을 따를 것 (일반 마크다운 표는 Notion에서 제대로 렌더링 안 됨).

```
<table fit-page-width="true" header-row="true">
	<tr>
		<td>기능</td>
		<td>설명</td>
		<td>사용 시기</td>
		<td>예시</td>
	</tr>
	<tr>
		<td>항목 A</td>
		<td>설명 내용</td>
		<td>언제 쓰는지</td>
		<td>구체적 예시</td>
	</tr>
</table>
```

### Callout 블록 활용

핵심 포인트, 팁, 주의사항은 Callout으로 강조함.
텍스트만 쭉 나열하면 독자가 중요한 내용을 놓치기 쉽기 때문임.

```
💡 핵심 팁
<callout icon="💡" color="green_bg">
	여기에 핵심 포인트나 중요한 팁을 씀
</callout>

⚠️ 주의사항
<callout icon="⚠️" color="yellow_bg">
	주의해야 할 내용
</callout>

🚨 금지/제약
<callout icon="🚨" color="red_bg">
	반드시 지켜야 하는 제약이나 금지 사항
</callout>
```

## 금지 사항

- 합쇼체(`~합니다`, `~입니다`, `~하세요`) 사용 금지
- 명령형(`~하십시오`, `~해야 합니다`) 사용 금지
- 내용 임의 생략 금지 — 소스의 모든 중요 정보를 포함할 것
- 긴 단락 서술 금지 — 불릿 포인트로 간결하게
- Notion Markdown 스펙 확인 없이 고급 블록 사용 금지
- 섹션 제목에 영어 병기 금지 — "세션 (Session)" 대신 "세션"으로만 쓸 것

## 완료 체크리스트

- [ ] 소스 내용 전체를 빠짐없이 파악했음
- [ ] Notion Markdown 스펙(`notion://docs/enhanced-markdown-spec`)을 확인했음
- [ ] 대섹션 제목이 `#` (H1) + `---` 구분선으로 작성됐음
- [ ] 핵심/주의 섹션 제목에 `<span color="red">` 색상 강조를 적용했음
- [ ] 모든 본문이 `-` 불릿으로 시작됐음 (단락 서술 없음)
- [ ] 문장 끝이 `~~했음`, `~~임` 등 구어체 서술형임
- [ ] 전문 용어에 괄호 설명을 달았음
- [ ] 여러 기능 정리 시 설명+사용 시기+예시 포함 통합 표를 활용했음
- [ ] Notion 페이지가 실제로 업데이트됐음
